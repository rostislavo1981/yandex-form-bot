# 📝 HANDOFF TEMPLATE

Шаблон записи «где остановились», который **каждая сессия обязана добавить в конец `PROGRESS.md` §HANDOFF NOTES** перед завершением.

Цель: следующий агент за 2 минуты понимает, откуда продолжить.

---

## Как заполнять

1. Скопируй блок ниже.
2. Вставь в `PROGRESS.md` в раздел HANDOFF NOTES **сверху** (свежие сверху).
3. Заполни все поля. Если поле не применимо — напиши «н/п», не удаляй.
4. Никакой воды. Только конкретика.

---

## Шаблон

```md
### [YYYY-MM-DD HH:MM] — <краткое название сессии>

**Агент:** <модель + версия, напр. Claude Sonnet 4.5>
**Ветка:** <phase-N-slug>
**Фаза:** Phase N — <название>
**Коммиты этой сессии:** <хэши через запятую или «см. git log --author=...»>

**Что сделано:**
- <пункт 1: конкретно, глаголом совершенного вида>
- <пункт 2>
- <пункт 3>

**Что НЕ сделано (из запланированного):**
- <пункт 1: почему не сделан — забыт / заблокирован / решено отложить>
- <пункт 2>

**Что сломано или требует внимания:**
- <баг, регрессия, TODO — с указанием файла и строки>
- <либо: «ничего»>

**Тесты:**
- Добавлено: <кол-во новых>
- Всего проходит: <N/M>
- Красные: <перечислить или «нет»>

**Открытые вопросы к пользователю:**
1. <вопрос, на который нужен ответ, чтобы продолжить>
2. <...>

**Следующий шаг:**
<Одно-два предложения: что делает следующий агент буквально с первого действия.>

**Файлы, изменённые в этой сессии:**
- backend/app/foo.py
- backend/tests/test_foo.py
- docs/max-mini-app-spec/PROGRESS.md

**Важный контекст, который не очевиден из кода:**
- <например: «MAX API вернул 502 на sendMessage — оказалось, что нужно передавать chat_id как строку, а не число. Задокументировано в ADR-008.»>
- <либо: «н/п»>
```

## Пример плохой записи (так НЕ надо)

```md
### 2026-07-15 — сделал фронт

Написал компоненты, всё вроде работает. Оставил кое-что на потом.
```

Проблемы: нет фазы, нет коммитов, нет тестов, нет «что дальше», нет файлов, нет вопросов. Следующий агент потратит час, чтобы понять контекст.
