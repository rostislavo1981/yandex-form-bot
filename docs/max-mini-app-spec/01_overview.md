# 01. Обзор продукта

## Цель MVP

Заменить длинную статическую Яндекс.Форму удобной Mini App в MAX и получить надёжный накопительный табель по каждому строительному объекту.

## Пользовательский сценарий

1. Ответственный нажимает видимую кнопку в общей группе или личном боте.
2. Открывается Mini App и проверяет `window.WebApp.initData` на backend.
3. Пользователь выбирает назначенный ему объект через поиск.
4. Выбирает допустимый этап этого объекта.
5. Добавляет строки техники и работ из динамических справочников.
6. Вводит персонал, грунт и комментарий.
7. Отправляет отчёт.
8. В группе появляется короткая карточка.
9. Данные сразу попадают в табель объекта.

## Роли

| Роль | Возможности |
|---|---|
| `responsible` | Сдать отчёт по назначенным объектам, видеть свои отчёты и табели |
| `manager` | Видеть все объекты, статус сдачи, табели и Excel |
| `admin` | То же, плюс импорт/экспорт справочников |

## Контроль сдачи

Для каждого активного назначения создаётся ежедневное обязательство:

```text
report_date + object_id + responsible_user_id
```

Статусы: `pending`, `submitted`, `late`, `missed`, `exempt`.

Если сотрудник отвечает за три объекта, система ожидает три отчёта. Утренняя сводка считает обязательства, а не уникальных людей.

## Динамические справочники

Все названия хранятся в PostgreSQL и могут меняться без релиза frontend:

- ответственные;
- объекты и поисковые псевдонимы;
- этапы и связь с объектами;
- подрядчики;
- техника;
- виды и способы работ;
- единицы измерения.

Excel используется для массового импорта с проверкой и для экспорта. У каждой записи есть стабильный `code`; переименование `name` не меняет исторические связи.

## Границы MVP

Входит: одна группа MAX, Mini App, динамические справочники, отчёты, групповые/личные кнопки, напоминания, утренняя сводка, табель по объектам, Excel, Docker Compose и HTTPS.

Не входит: полноценная админка, фото, согласование, черновики между устройствами, LLM, Яндекс.Формы, Яндекс.Диск, multi-tenant.
