# 15. Группа, кнопки и расписание

## Обязательное условие

Все ответственные находятся в одной группе MAX. Бот — администратор группы с минимальными правами `write` и `pin_message`. В `.env` хранится `MAX_GROUP_ID`.

## Видимые кнопки

Групповой пульт закреплён в группе. Личный пульт отправляется на `/start`, `/menu`, после отчёта и после действий. Основной сценарий не требует знания slash-команд.

### Групповой пульт

```text
[ 📝 Заполнить отчёт ]
[ 📊 Статус сегодня ] [ 📅 Табель ]
[ 📥 Excel ]          [ 👥 Кто не сдал ]
[ ℹ️ Помощь ]
```

### Личный пульт

```text
[ 📝 Заполнить отчёт ]
[ 📋 Мои отчёты ] [ 📅 Мой табель ]
[ 🏗 Мои объекты ] [ 📥 Excel ]
[ ↩️ Рабочая группа ]
```

## Карточка отчёта

Создаётся через transactional outbox и публикуется только после commit. Содержит дату, объект, этап, ФИО и короткие суммы. Повторная публикация ограничивается ключом `report:{report_id}:{group_id}`; временные ошибки MAX повторяются worker.

## Расписание

Время и часовой пояс хранятся в `max_groups`, timezone по умолчанию `Europe/Moscow`. Все часы — локальное время группы.

| Job | Время | Действие |
|---|---|---|
| morning | `00:05` | Создать obligations на текущий день из активных назначений. |
| evening-reminder-1 | `20:00` | Первое вечернее напоминание для still-pending. |
| evening-reminder-2 | `20:30` | Второе напоминание только если после первого остались pending. |
| morning-summary | `08:00` | Закрыть вчерашние pending как `missed`; опубликовать итог предыдущего дня. |

Контейнер `scheduler` запускает APScheduler и держит HTTP-вызовы к `/api/scheduler/*` внутри той же сети Docker.

## Счётчики

`expected` — число obligations; `submitted` включает вовремя отправленные; `late` показывается отдельно; `missing` — pending/missed. Если человек ведёт три объекта, это три ожидаемых отчёта.

## Идемпотентность

Каждая публикуемая задача имеет уникальный `notification_key`. Перед отправкой scheduler:

1. Получает PostgreSQL advisory lock (по `lock_id` задачи).
2. Проверяет `notification_log` — если ключ уже `sent`, пропускает.
3. Отправляет сообщение через MAX Bot API.
4. Фиксирует external message ID и статус `sent`.

Повторный запуск безопасен. Временные ошибки MAX не помечают ключ как `sent`, и worker/scheduler retry продолжает попытки.

## Проверка перед production

- Бот добавлен администратором группы и может писать/закреплять.
- В группе постоянно доступен закреплённый пульт.
- В личном боте виден персональный пульт.
- `open_app` работает из обоих мест.
- После заполнения приходит одна краткая карточка.
- Reminder содержит кнопку заполнения.
- Утренняя сводка показывает правильные числа и ФИО.
