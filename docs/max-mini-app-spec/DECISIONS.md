# DECISIONS — ADR

Свежие решения имеют приоритет. Старые альтернативные треки отменены.

## ADR-001. PostgreSQL как источник истины

**Статус:** accepted.

Каталоги, назначения, obligations и отчёты хранятся в PostgreSQL. Excel используется только для проверяемого импорта/экспорта. SQLite и Excel-as-database запрещены.

## ADR-002. Mini App-first

**Статус:** accepted; отменяет Bot-first.

Длинные динамические списки и повторяемые строки требуют формы с поиском. Бот отвечает за кнопки и уведомления, а не за длинный опрос.

## ADR-003. Один Python codebase, два процесса

**Статус:** accepted.

FastAPI app и scheduler запускаются отдельно из одного image. Scheduler не работает как background task API, чтобы исключить дубли при масштабировании.

## ADR-004. Нормализованное хранение, динамический табель

**Статус:** accepted.

В БД нет колонок по дням. Табель строится из строк отчётов отдельно по объекту. Разные единицы не суммируются; personnel total — человеко-дни.

## ADR-005. Видимые кнопки обязательны

**Статус:** accepted.

В группе закреплённый пульт, в личном чате восстанавливаемый пульт. Slash-команды — резерв. Бот хранит message IDs и редактирует сообщения.

## ADR-006. MAX production через webhook

**Статус:** accepted.

Long polling только для диагностики. Production: HTTPS webhook с secret, idempotent handlers и official REST API `platform-api2.max.ru`.

## ADR-007. Официальная проверка Mini App initData

**Статус:** accepted; отменяет все Telegram-подобные и phone-check формулы.

Используется `window.WebApp.initData` и двухступенчатый HMAC из официального `dev.max.ru/docs/webapps/validation`: secret key через `WebAppData`, затем подпись отсортированных launch params. Phone HMAC — отдельная функция и к initData не применяется.

## ADR-008. Стабильные codes и snapshots

**Статус:** accepted.

Связи Excel и БД строятся по immutable `code`. Удаление каталогов заменено `active=false`. Report rows сохраняют snapshot names.

## ADR-009. Obligations как основа контроля

**Статус:** accepted.

Expected/missing считаются по `дата + назначение ответственный–объект`. Один человек с тремя объектами создаёт три ожидаемых отчёта.

## ADR-010. Короткие линейные итерации

**Статус:** accepted.

Единственный backlog I00–I22. Одна итерация — тестируемый результат и один коммит. Агент не начинает следующую итерацию автоматически.

## ADR-011. Упрощённая web-админка внутри Mini App

**Статус:** accepted.

Для управления динамическими справочниками создана лёгкая страница `/admin/catalogs` в том же React-приложении. Она не отменяет Excel bulk-import (ADR-001/008), а дополняет быстрым поштучным редактированием. CRUD эндпоинты изолированы в `app/api/admin_catalogs.py`, доступ ограничен ролями `manager`/`admin`, удаление — soft-delete (`active=false`).

## Добавление решения

Новое ADR обязано указать, какое старое решение оно отменяет, почему и какие документы/миграции нужно обновить.
